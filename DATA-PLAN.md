## Tested sources
### Bundled speech synthesis tool for recorded question audio
**Used by**: build time asset generation only. Each scenario question, each chart drill prompt, and each explanation becomes its own MP3 under client/src/assets/audio, imported by the client and played from an audio element. One recording per playable unit, speaking exactly the text shown with it.
**Test command**: `/opt/hatch/bin/tts speak --output /tmp/test-pmp.mp3 --text-stdin` with a short sample question as stdin
**Sample output**: `{"ok":true,"bytes":39013,"voice":"avocado_v2:MAI_03","path":"/tmp/test-pmp.mp3"}`, MPEG layer III audio, 64 kbps, 24 kHz, about 2.5 seconds for one short unit
**Processing**: A generation script reads the authored bank, builds each spoken text from the exact displayed fields, and calls the tts CLI with limited parallelism. Files use stable names such as s01-q.mp3, s01-e.mp3, c01-q.mp3, c01-e.mp3. A generated audio map module imports them by question id. If synthesis returns the cannot generate message, stop and report failure per the spoken audio reference instead of substituting device voices for fixed text.

### Browser speech recognition for spoken answers (runtime device capability)
**Used by**: practice screen voice answer button
**Test command**: browser API (SpeechRecognition / webkitSpeechRecognition), cannot be probed from the server; the UI feature detects it at runtime
**Sample output**: no server output; design assumes it may be absent or denied
**Processing**: Map a short utterance to an option by letter forms, ordinal forms, or a distinctive keyword match against option text. Show the heard transcript and the matched option, and score the matched option. Tap to answer is always a full equivalent path.

### Original question bank (authored content, no external dataset)
**Used by**: startSession, submitAnswer, and gap analysis actions
**Test command**: none. No external question source and no Mulcahy book text is used.
**Sample output**: 30 original scenario questions (People 10, Process 12, Business Environment 8) plus 10 process chart drill items (2 per process group). Each scenario item carries domain, format tag (next, avoid, best, first), topic tag naming the specific process or topic for gap analysis, process group where relevant, scenario, stem, four options, correct index, a concept first explanation covering why the other options fail, and an exam trap note. Each chart item carries its process group, a spoken activity prompt, four process group options or process options, correct index, and a short explanation.
**Processing**: Bank lives in server code as a constant. Sessions are served without correct answers; submitAnswer checks on the server and returns correctness, the correct option, the explanation, and the trap note.

### Original glossary (authored content, no external dataset)
**Used by**: getGlossary action, the Glossary page, and term lookups inside practice questions and explanations
**Test command**: none. Term selection covers the core PMP vocabulary the question bank uses and the term pairs exam focused study methods flag as easily confused (Validate Scope versus Control Quality, contingency versus management reserve, crashing versus fast tracking, integrated change control and the Change Control Board, and similar). The Mulcahy method informs which terms are emphasized and how pairs are flagged; no book glossary text or definitions are reproduced.
**Sample output**: 51 original terms, each with a plain language definition written for this app, a domain at the July 2026 weights, a process group where one applies, an easily confused partner where relevant, an exam trap note where relevant, and matching aliases used only on the server.
**Processing**: Glossary lives in server code as a constant next to the bank. getGlossary serves the display fields. startSession attaches the ids of terms matched in each question's scenario, stem, and options; submitAnswer attaches the ids matched in the explanation and trap note. Each term also has one recording (term plus definition, exactly the text shown) generated with the same bundled speech tool and voice as the question audio, stored as g-<term-id>.mp3 under client/src/assets/audio and imported through client/src/glossaryAudio.ts.

## Long-term data behavior
- **Refresh policy**: No scheduled refresh. Records change only when the user answers inside the artifact. The glossary is static authored content served by getGlossary; it stores nothing.
- **Growth**: One sessions row per practice set or mock exam (kind scenario, chart, formula, or mock) and one attempts row per answer (question id, kind, domain, topic, process group, chosen option, correct flag, answer mode, created at). Aggregates are computed from attempts. Mock exam answers are submitted in one burst at finish time, so their created at values cluster at the end of the exam; their session row carries the exam start time.
- **Ordering**: History newest first. Domain report in ECO order. Chart drill always presents items in process group order: Initiating, Planning, Executing, Monitoring and Controlling, Closing. Gap analysis lists weakest topics first.
- **Time semantics**: Timestamps are creation instants in timestamp_ms, rendered viewer local.
- **Scoring semantics**: Domain accuracy is correct divided by attempted in that domain. Weighted overall is 0.33 People plus 0.41 Process plus 0.26 Business Environment accuracy, renormalized over attempted domains with a note when a domain has no attempts yet. Scenario mix uses largest remainder allocation against 33, 41, 26: a 10 question set draws People 3, Process 4, Business Environment 3; a 20 question set draws 7, 8, 5. Gap analysis aggregates attempts by topic tag and by process group, flags any topic with accuracy under 70 percent once it has at least 2 attempts, and names the restudy list in weakest first order.
- **Imagery**: Imagery not needed: a voice first practice tool whose visual focus is the player, the answer options, and the process chart. No photographic subjects are depicted.
